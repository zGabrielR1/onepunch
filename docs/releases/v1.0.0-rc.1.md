# Onepunch 1.0.0-rc.1

Release candidate for the personal Android workout logger, web companion and
Linux amd64 sync API. This is a test version, not a stable 1.0 release.

## Candidate scope

The 0.3.0 logging/routine/history/backup feature set remains the baseline.
Reviewed native increments add manual rest start and 30-second shortening/extension,
exercise replacement inside routine drafts, factual comparisons of the last two
saved exercise sessions and stricter local-envelope parsing. These changes require
fresh hosted verification and device QA; historical 0.3.0 results do not apply.

Unreadable local workspace/draft screens now offer original-record export for
assisted recovery. This preserves raw stored values without parsing or replacing
them. The recovery document is distinct from an importable workout backup.

Release infrastructure now includes an owner-signed non-debuggable candidate
workflow, certificate/version checks, extracted Linux bundle smoke testing,
artifact hashes in verification metadata and promotion of exact tested files.
Stable promotion requires a complete device report matching the APK hash/source
and successful hosted candidate run. No signing key or device pass is implied by
these source changes. See `docs/RELEASE_STATUS.md` for open gates.

## Which APK is this?

The existing Hosted prerelease workflow produces an explicitly named `-debug.apk`
with an ephemeral debug certificate. The Signed release candidate workflow produces
an APK without that suffix and records the expected owner certificate fingerprint.
Read `verification.json` and `apk-signature.txt` from the same artifact set.
Neither workflow makes an APK device-tested merely by compiling it.

## Installation and data

Android 8+; Português (Brasil), kg. Signature differences may block updates from
older debug APKs. Export a native JSON backup and verify restore on a separate test
profile/device before replacing an installation. Do not uninstall the only copy
of personal records. Sync excludes active workouts and routine drafts.

Signed RC-to-final updates require the same owner signing key, application ID and
a higher Android versionCode. See `docs/RELEASE_OPERATIONS.md` for the handoff.
The native backup is plaintext; keep exported personal files in a trusted place.

## Limits

Device/picker/interruption, accessibility and upgrade QA remain pending until a
report identifies this exact APK. Background rest notifications are not promised.
Web has a smaller feature set than native (see the client support inventory).
The API is a personal single-process service with no account authentication;
keep its default loopback binding. The Linux bundle supports amd64 only.
