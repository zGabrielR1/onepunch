# Onepunch 1.0.0-rc.2

Release candidate for the personal Android workout logger, web companion and
Linux amd64 sync API. This is a test version, not a stable 1.0 release.

## Candidate scope

Catalog expanded from 60 to 100 exercises, all rep-based kg × reps movements
covering Peito, Costas, Pernas, Ombros, Braços and Core with Barra, Halteres,
Polia, Máquina and Peso corporal options. Timed holds (e.g. planks) were
intentionally not added as ordinary exercises because the completed-set contract
records kilograms and repetitions.

Routine templates expanded from nine to 17 editable examples, each with seven
distinct exercises: the existing Superior A/B, Inferior A/B, Empurrar, Puxar,
Corpo inteiro A/B and Com halteres, plus PPL Empurrar/Puxar/Pernas and the
five-day personalized split — Dia 1 Pernas, Dia 2 Costas e bíceps,
Dia 3 Peito e tríceps, Dia 4 Costas e bíceps B, Dia 5 Peito, tríceps e extras
(ombros e core) on the last day. Templates are editable examples, not
personalized training advice.

Native smallest text raised from 10sp to 11sp (12sp for metric labels:
Eyebrow, navigation labels, weekly day labels and history dates) for narrow
screenshots and large-font readability. Active-set inputs remain 16sp with
previous performance on a second line.

Hardened web finished-history sync from the previous working tree is included:
different content under an existing workout ID rejects the whole local merge
without replacing local data, with conflict feedback and retry.

Additional web hardening excludes invalid historical rows from previous-set
suggestions, rejects fractional rest seconds, and prevents a recovered active
workout ID from overwriting finished history. Finish conflicts retain the active
session with feedback. Domain and browser regressions passed; a fresh signed build remains required.

Assisted pull-ups and chin-ups now show kg de assistência. Their completed sets
remain in history and suggestions, while assistance is excluded from lifted-volume
totals and highest-load records. Existing stored values and IDs are unchanged;
totals may decrease because this corrects the calculation. Update both clients for
consistent metrics. Android load/volume comparison is omitted for these exercises.
Android JVM and browser regressions passed; exact signed-artifact device QA remains pending.

Android sync now rejects conflicting finished history at every timestamp,
retains identical local records and shows explicit conflict feedback. Finishing
cannot overwrite history with a colliding active ID. Backup restore and sync
share numeric-equivalence rules. Debug compilation and JVM regressions passed; device conflict feedback QA remains pending.

Web recovery preserves unreadable empty/nested local records, and malformed sync
responses are rejected before applying state. Unfinished inputs and rest deadlines
remain intact. Domain and browser regressions passed.

## Development verification — 2026-11-08

Debug APK compilation and 77 Android JVM tests passed. Host checks passed 16 web
regressions, 13 release-tooling tests, production web build, Go race tests and
233 browser assertions (181 workflows + 52 catalog/layout). Runs used the enforced
3 GiB cap with no swap. The web run's 53 recorded source hashes match the reviewed
working tree. See `docs/qa/v1_0_0_rc_2_automated.json` for evidence and limitations.
These development results do not replace fresh signed-candidate and device QA.

## Which APK is this?

The Signed release candidate workflow produces a non-debuggable release APK
recorded with the owner certificate fingerprint and verification metadata.
Authorized signed prerelease publication uploads those same checked files only
after the hosted build succeeds; it does not rebuild or substitute a debug APK.
Read `verification.json` and `apk-signature.txt` from the same artifact set.
Hosted checks run on GitHub, never on the development PC. Device UI QA remains
separate and pending until a report identifies this exact APK. See
`docs/RELEASE_OPERATIONS.md` and `docs/RELEASE_STATUS.md`.

## Installation and data

Android 8+; Português (Brasil), kg. Fresh workspaces receive the 17 seeded
templates; existing workspaces are never reseeded and their routines, archived
items, active workout and finished history remain unchanged. New templates are
available through Modelos prontos / Usar modelo, which opens a new editable
copy before saving. Signature differences may block updates from older debug
APKs. Export a native JSON backup and verify restore on a separate test
profile/device before replacing an installation. Sync excludes active workouts
and routine drafts. Restart the personal API with the updated catalog before
syncing newly added exercise IDs.

## Limits

Device/picker/interruption, accessibility and upgrade QA remain pending until a
report identifies this exact APK. Background rest notifications are not promised.
Web has a smaller feature set than native (see the client support inventory).
The API is a personal single-process service with no account authentication;
keep its default loopback binding. The Linux bundle supports amd64 only.
